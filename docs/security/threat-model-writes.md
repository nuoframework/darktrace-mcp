## Boundaries and mandatory execution sequence

Reuse B1 arguments/stdio, B2 secrets, B3 pinned verified appliance HTTPS, B4 untrusted appliance bytes, B5 export/recipient, B6 build/dependencies and B7 host/provider egress. The approval reply crosses B1: transport correlation authenticates a client response, not a person. stderr is a local audit sink; external retention crosses the operator-controlled environment. No HTTP listener or new OAuth identity is introduced.

Validate input and static descriptor, enforce profile and target restrictions, then return unsigned preview if requested. Critical execution checks the circuit breaker, validates/reserves the preview, admits a bounded approval request, obtains approval, rechecks expiry/policy and immutable arguments, rechecks the breaker and reserves write budgets, awaits audit start, and only then builds/signs/transmits once. Mandatory pre-audit failure consumes the preview and cannot send. Ordinary writes enforce the same dispatch/rate/audit gates without critical preview/approval. Use a frozen validated request object throughout; neither approval UI nor a later caller can mutate it. Preview does not lock appliance state: changed upstream state remains a TOCTOU risk unless the operation supports an independently validated conditional update.

Pending acceptance refinements beyond the supplied design: operator-owned per-operation target allow/deny restrictions and finite bulk cardinality must bound blast radius; never let telemetry redefine protected targets. A process-local circuit breaker should open after three consecutive failed/unknown mutation outcomes, deny further writes until operator restart, and leave reads available. Bound elicitation to one pending request per session and four per process with no unbounded waiting queue, at most the remaining 30 s call deadline, and never beyond preview expiry. These are explicit release requirements, not described implemented features. ST-17/ST-22/ST-28 are NOT RUN gates if missing.

## Evidence and acceptance

[ST-17–29](security-test-plan-writes.md) define measurable contracts. Preserve original tests; separately scope old blocked-shape/profile oracles to the historical baseline and add new-surface tests rather than weakening them to pass. Obtain at least two independent design-review rounds, implementation review on exact hashes, isolated adversarial receipts, fresh artifact/Docker evidence, provider/ACL decisions and separately authorized non-production lab evidence. Lab writes require exact operations, sacrificial targets, created-by-test objects, finite budget, undo and verified cleanup; no live work is authorized here.

All controls and tests here are unvalidated. Host-mode approval assurance, combined sensitive/write data flow, target restrictions/circuit breaker, EMAIL schema provenance, 78-operation manifest and S4/S5/S6 compatibility remain finite release gates. Documentary completeness is not closure of implementation findings or acceptance of residual risk.
