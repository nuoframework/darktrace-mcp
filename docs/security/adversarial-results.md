## Limits of TLS evidence

The coordinator explicitly authorized the helper in `test/security/network.test.mjs`: initialize the production connector with a validated synthetic private snapshot, then replace only its dedicated Agent on that test instance so lookup reaches loopback. The production `request` method still controls HTTPS, configured hostname/SNI, `rejectUnauthorized:true`, certificate hostname verification and signed HTTP headers. The test process trusts the synthetic CA only through `NODE_EXTRA_CA_CERTS`. There is no production loopback config or tool argument.

This is **real TLS/certificate/SNI/HTTP-byte evidence**, together with separate production snapshot/lookup tests. Since the Agent destination mapping is deliberately substituted, it is **not end-to-end proof that a production socket reached an approved private IP**. That remaining pinning evidence must use an authorized isolated network fixture with a real private address. TLS failures open handshake sockets but deliver zero signed HTTP bytes. Bootstrap trust, same-user compromise and arbitrary trusted NODE_OPTIONS code are not solved by the adapter.
