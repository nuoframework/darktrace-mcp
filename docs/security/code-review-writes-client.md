# Independent security code review: writes, sensitive reads, client and approval flow

**Verdict: NOT READY.** The review found security-control gaps in approval display/expiry, sensitive EMAIL projection, target/bulk policy, failure circuit breaking, elicitation resource bounds, and audit binding. The supplied 7.1.0 lab observations also invalidate the current S6 signing form and show the implemented S4 form is rejected by the appliance.

## 2. Controls verified

| Area | Evidence and result |
|---|---|
| **Profile and operation gates** | `profiles.ts` requires `sensitive` for Advanced Search and EMAIL reads; critical operations require both `write` and `critical`. `callTool` authorizes against the code-owned catalogue before validation and again before dispatch. No model-supplied profile or approval field can grant access. |
| **Preview handles** | `guard.ts` uses 128-bit random IDs, binds operation plus canonical validated path/query/body/content type, rejects expiry at equality, and deletes a handle synchronously before awaiting approval. A duplicate concurrent use therefore loses the handle. The post-approval TTL gap is CR-04. |
| **Write admission and retries** | `consumeWriteSlot` is synchronous, uses a rolling 60-second window, shares the ordinary budget with critical writes, and adds a three-per-minute critical sub-limit. The HTTP client does not retry POST or DELETE. The per-client versus per-process scope is CR-12. |
| **S5 502 behavior** | The supplied lab summary says the DELETE side effect was applied despite HTTP 502. The client maps 502 to a safe server error; the tool layer, after pre-audit, returns `outcome:"unknown"` and advises a read before retry. DELETE has one attempt and is not retried. This is the correct conservative result when the response cannot prove whether an effect happened. |
| **Query and path construction** | Ordered pairs and repeated query keys are preserved; query wire encoding uses RFC3986 escapes; S4 JSON bytes are serialized once and sent as signed; path validation in the production request path rejects traversal, encoded traversal, controls and separators. Tests cover ordinary and multi-encoded traversal attempts. The lab evidence changes the S6/S4 compatibility conclusions in CR-02/03. |
| **Network and resource controls** | TLS verification is explicit, DNS answers are validated and pinned, redirects are rejected, ambient proxies/TLS bypass settings are rejected, retries are bounded to GET, and response/input/output ceilings are enforced. Typecheck, unit, MCP, and security suites passed apart from the three platform skips described above. |
| **EMAIL lab response** | Per the supplied summary, a 403 after a valid HMAC means authentication was accepted and appliance authorization denied the request. That is not evidence of a signer failure; the unreviewed response projection remains a separate concern in CR-05. |
