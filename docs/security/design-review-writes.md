# Writes and sensitive-read design review (DR-W)

**Status:** independent design review (security architecture) of the full-API change. Date: 2026-10-06. Reviewer: an independent reviewer (a different model from the authors of the code and of the writes supplement.
**Verdict:** **CONDITIONAL GO** for reversible writes. **CONDITIONAL GO** for tags, subnets and intel feed, after DR-W-01/02/04 are fixed. **NO-GO** for Antigena/RESPOND and email actions. **CONDITIONAL GO** for sensitive reads in a profile **without** `write`. **NO-GO** for releasing `all` or any other sensitive+write union until DR-W-03 is fixed (§6).
**What this is not:** this is not a test result, not a lab result and not an acceptance of risk. I ran no test suite and contacted no appliance. One finding (DR-W-01) was reproduced with a standalone copy of the code path, described in §3. Every ST-17–29 row stays NOT RUN. I did not change `src/` or `test/`.

## 4. MR-06: should `all` warn or require acknowledgement?

**Recommendation: require an explicit acknowledgement, plus session taint. A warning is not enough.**

- **A warning does not reach the person who decides.** Stdio servers write stderr into host logs that operators rarely read, and today the code emits **no warning at all**. MR-06 (Medium) recommended a startup **error** for sensitive+write. A15 reversed that but put nothing in its place, while saying the risk is "not accepted here". In practice, release accepts it by default.
- **The exposure is concrete, not theoretical.** Sensitive reads (PCAP base64, email bodies, Advanced Search) and irreversible, appliance-wide free-text sinks (comments) coexist under the default `writeApproval=host`, so no human sees the write. TMW TM-24 itself says critical approval cannot protect direct medium/high sinks.
- **Proposed contract:**
  1. Any configuration whose effective profiles include `sensitive` and `write` fails at startup unless `DARKTRACE_ACCEPT_COMBINED_PROFILE=TM-24` (an exact token naming the threat) is set. `doctor`/`--check-config` print `combinedProfile:true, acknowledged:true`. The installer's `all` preset writes this variable only after an explicit yes.
  2. **Session taint** (new TM-32): after the first successful sensitive read in a process, free-text sinks (comment `message`, tag `name`/`description`, device `label`, intel-feed text fields, subnet `label`, email-action body) require elicitation, falling back to denial. Non-text writes (ack, pin, tag-entity membership by id) are unaffected, which keeps the cost low for analysts.
  3. TM-24 residual then becomes: "an approved human copy remains possible", which is an organizational decision and can be recorded.
- Without (2), (1) alone is the minimum for any release that enables `all`.
